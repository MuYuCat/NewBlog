# 企业级全栈个人门户/博客系统大纲 (Personal Portal & Blog Architecture)

本大纲在原有基础上，针对 **游戏数据接入、文档管理系统、资源收藏系统** 三大板块进行了深度架构优化，并保留了高度的可扩展性，支持未来功能模块的无缝接入。

---

## 1. 系统核心三大板块设计 (Core Modules)

### 板块一：游戏轨迹 (Game Hub)
*   **目标:** 聚合展示 PS (PlayStation) 与 Steam 的游玩记录、成就及愿望单。
*   **功能亮点:** 
    *   **自动同步:** 定时任务 (Cron Jobs) 从 Steam API 及第三方 PSN API 爬取数据。
    *   **愿望单跟踪:** 跨平台愿望单汇总，支持自定义降价提醒。
    *   **游玩看板:** 统计总游戏时长、奖杯达成率等可视化图表。

### 板块二：知识智库 (Content Management System)
*   **目标:** 高性能文档系统，支持长文笔记、技术文档的发布与版本管理。
*   **功能亮点:**
    *   **多模式编辑器:** 支持富文本与 Markdown，内置语法高亮与实时预览。
    *   **版本历史:** 文档修改记录追踪，支持查看差异 (Diff) 与一键回滚。
    - **结构化管理:** 支持树状目录结构、多层级分类、标签云、全文搜索。

### 板块三：资源宝库 (Resource Hub)
*   **目标:** 记录有趣的网站链接、外链文章，并进行系统化分类与编辑。
*   **功能亮点:**
    *   **智能剪藏:** 输入链接自动抓取网站标题、描述及封面图 (Open Graph Scraper)。
    *   **分类体系:** 灵活的分类管理，支持移动端快速收藏、添加评论。
    *   **快照预览:** 记录收藏时的原始元数据，防止原网站失效。

## 2. 开发环境与包管理 (Development Environment)

为了确保多项目协同的高效与稳定，统一采用以下工具链：

*   **Node.js 版本管理:** **nvm** (用于切换不同项目所需的 Node 版本，推荐使用 v20 LTS)。
*   **包管理工具:** **pnpm** (基于内容寻址的存储，极速且节省磁盘空间，[Monorepo](./知识点.md#monorepo) 标配)。
*   **代码仓库模式:** **[Monorepo](./知识点.md#monorepo) (pnpm workspaces)**。前台、后台、API 位于同一个仓库，方便共享类型定义（Shared Types）与工具类。
*   **镜像源加速:** 统一使用 `https://registry.npmmirror.com` 以保证国内下载速度。

## 3. 优化后的项目架构 (Optimized Architecture)

采用 **[Monorepo](./知识点.md#monorepo) (pnpm workspaces)** 架构，确保前后端类型定义的统一性与复用。

### [后端 API (NestJS - `blog-api`)](./需求.md#api)
*   **模块化核心 (Module-Based):**
    *   `GameModule`: 对接外部游戏 API，处理复杂的数据清洗与缓存逻辑。
    *   `DocModule`: 负责树形结构算法及文档的版本管理机制。
    *   `ResourceModule`: 集成 `Puppeteer` 或 `Cheerio` 爬虫服务，用于外链元数据提取。
*   **异步任务管理:** 
    *   使用 **BullMQ** 管理高耗时的爬虫与定时任务，避免影响主接口性能。
*   **存储引擎:** 
    *   MySQL 8.0 存储核心业务数据，Redis 负责接口缓存及任务队列状态。

### 前台 Web (Vue 3 - `blog-web`)
*   **布局解耦:** 
    *   采用 **Module-Based Routing**，为游戏看板、文档阅读器、资源卡片流定制独立的 Layout。
*   **响应式与交互:**
    *   `Vue 3.4` + `Vite` + `Pinia` 组合，配合 `GSAP` 打造丝滑的游戏卡片动效。

### 后台 Admin (React - `blog-admin`)
*   **管理核心:**
    *   使用 `React 18` + `Shadcn/UI` 开发，侧重于系统同步日志查看、文档版本对比与采集规则配置。
*   **低代码倾向:** 
    *   集成 `React Hook Form` + `Zod` 实现复杂的采集表单校验。

### 移动端 (uni-app - `blog-app`)
*   **定位:** 强调“碎片化”录入与查看，作为 PC 端的辅助工具，侧重于资源链接的快速收藏与游戏状态查看。

## 4. 数据库扩展设计 (Database Schema)

*   **Game 系统:** `games` (基础库), `play_stats` (统计), `wishlist_track` (愿望单)。
*   **Doc 系统:** `docs` (主表), `doc_versions` (版本快照), `doc_tree` (目录结构)。
*   **Resource 系统:** `bookmarks` (收藏), `bookmark_meta` (元数据快照), `categories` (分类)。

---

## 5. 后期扩展性 (Extensibility)

1.  **钩子机制 (Hook Ready):** 预留插件入口，未来可快速接入“电影记录”、“运动健康”等模块，只需在 API 侧注入新 `Module`，前端注入新 `Route` 即可。
2.  **微前端支持:** 架构上预留微前端规范，若单板块复杂度过高，可拆分为独立子应用部署。
