# 游戏轨迹 (Game Hub) 深度技术蓝图

> **定位**：全栈自动化游戏生涯聚合系统。通过主实体映射技术，打破 PSN、Steam、Switch 等平台的壁垒，实现“以游戏为中心”的深度数字化档案。

---

## 1. 核心数据架构 (Data Schema)

采用 **“主实体-平台关联”** 的多对多映射模型，解决同款游戏多平台数据共存的问题。

### 1.1 Master Game (主游戏实体)

- **ID**: 内部自增 ID。
- **IGDB_ID**: 全球唯一标识符（用于跨平台自动匹配的核心锚点）。
- **Title**: 标准化中文/英文名称。
- **Summary**: 游戏简介（支持 Markdown，来自 IGDB 或手动录入）。
- **Cover**: 4K 高清封面图 URL。
- **Rating**: 个人评分 (0.0 - 10.0)。
- **Review**: 深度评测协议（关联 Article 表或独立 LongText）。

### 1.2 Game Platform (平台关联实体)

- **Platform_Type**: `PS5`, `Steam`, `Switch`, `PC`。
- **External_ID**: PSN 的 `NPWR` 码、Steam 的 `AppID` 等。
- **Play_Time**: 该平台总游玩时长（小时）。
- **Progress**: 0 - 100%（奖杯/成就进度）。
- **Status**: `WANT` (想玩), `PLAYING` (在玩), `COMPLETED` (通关), `PLATINUM` (白金/全成就), `DROPPED` (搁置)。
- **Last_Played**: 最后一次游玩时间。

### 1.3 Achievement (成就/奖杯)

- **Name**: 名称。
- **Rarity**: 稀有度（白金/金/银/铜 或 普通/稀有/传说）。
- **Earned_At**: 达成时间点。

## 2. 自动化同步逻辑

### 2.1 抓取管线

1.  **Steam Sync**: 使用官方 Web API，通过 `SteamID` 抓取最近 2 周游玩及全库时长。
2.  **PSN Sync**: 使用 `psn-api` 模拟 SSO 登录，通过 `NPSSO` 抓取最近奖杯更新。
3.  **IGDB Enrichment**: 抓取到新游戏时，自动调用 IGDB API 获取标准化 ID、高清封面及分类元数据。

### 2.2 跨平台匹配算法

- **L1 物理匹配**: 检查 `external_id` 是否已存在。
- **L2 身份匹配**: 通过 IGDB 搜索接口对齐 `igdb_id`。如果相同，则自动合并到同一 Master Game 下。
- **L3 模糊匹配**: 针对无法对齐 ID 的游戏，通过标题相似度 (>90%) 在 Admin 后台标记为“疑似同款”，由管理员一键合并。

## 3. 后台管理系统 (blogAdmin) 模块

### 3.1 游戏实验室 (Game Lab)

- **Bento 列表**: 展示所有游戏档案，支持按“平台”、“状态”快速过滤。
- **一键聚合**: 选中多个平台记录，手动合并至一个 Master Game 实体。
- **同步看板**: 实时显示 Steam/PSN 的连接状态及同步日志。

### 3.2 档案精修

- **Markdown 编辑器**: 撰写游戏心得，支持 Word 协议导入。
- **封面实验室**: 手动调整封面裁剪位置，适配前台 Bento Grid。

---

## 4. 前台视觉表现 (blogWeb)

### 4.1 焦点画廊 (The Spotlight)

- **视觉**: GSAP 视差横滑卡片。展示当前正在攻略（Status=PLAYING）的高热度游戏。
- **背景**: 采用封面图的模糊处理 + Canvas 动态粒子。

### 4.2 数据看板 (Trophy Wall)

- **统计块**: 展示“白金总数”、“全成就完成率”、“本年游戏时长趋势图（ECharts）”。
- **物理奖杯**: 点击统计块，进入 **Matter.js 物理墙**。所有的奖杯图标像硬币一样散落在屏幕底部，用户可以用鼠标拨动它们。

### 4.3 游戏详情协议 (Game Overlay)

- **交互**: 采用非跳转的侧滑或全屏弹窗。
- **视觉**: 左侧固定展示平台图标及进度，右侧流式加载成就时间线与心得博文。

## 6. 平台健康监控系统 (Platform Health Monitoring)

为了确保账号资产安全，系统必须实时感知 PSN/Steam 的账号状态，并提供多级响应机制。

### 6.1 状态判定矩阵

系统基于抓取过程中的协议反馈，将账号状态分为以下四级：

| 状态                     | 标识        | 判定逻辑                                   | Admin 处理建议                           |
| :----------------------- | :---------- | :----------------------------------------- | :--------------------------------------- |
| **健康 (Healthy)**       | `SUCCESS`   | 最近一次同步 200 OK                        | 展示绿色心跳图标                         |
| **预警 (Warning)**       | `WARN`      | 出现 API 超时或 Token 剩余有效期 < 7 天    | 黄色高亮，提示续期 Token                 |
| **限流 (Throttled)**     | `RATELIMIT` | 命中平台 429 错误                          | 蓝色高亮，自动倍增下一次冷却时间         |
| **风控警告 (High Risk)** | `DANGER`    | 命中 401/403 且重试失败，或账号需 2FA 验证 | 红色闪烁，立即封禁自动同步，强制人工干预 |

### 6.2 Admin 监控仪表盘功能

- **心跳监控**: 在“游戏实验室”顶部展示各平台的实时连接状态。
- **异常回溯**: 点击平台图标可查看最近 10 次的同步原始日志及详细报错（如：`NPSSO_EXPIRED`）。
- **紧急刹车**: 管理员可一键物理切断所有自动同步，以应对极端的平台封禁策略。

### 6.3 接口风险矩阵 (PSN 专项)

所有非官方接口共用统一认证网关（NPSSO/AccessToken），风险等级如下：

| 接口         | 风险 | 行为特征           | 防护逻辑                           |
| :----------- | :--- | :----------------- | :--------------------------------- |
| **奖杯同步** | 中   | 数据量大、涉及翻页 | 强制单次分页间延迟 1s              |
| **用户信息** | 低   | 单次轻量级请求     | 仅在登录态变更时拉取               |
| **好友状态** | 高   | 易诱发高频轮询     | **严格禁止自动轮询**，仅限手动查看 |

## 7. 性能与安全准则 (已更新)

### 7.1 敏感信息加密

`NPSSO` 等 Token 必须加密存入数据库，仅在后端运行时解密。

### 7.2 幂等请求与环境锁

- **生产环境 (`PROD`)**: 强制 120 分钟长 CD，保护账号资产。
- **开发环境 (`DEV`)**: 强制 10 分钟短 CD，防止调试导致的高频误伤。
- **物理共用**: 无论环境，均查询同一数据库锁，防止本地调试刷爆线上配额。

### 7.3 宁可断网，不予封号 (熔断机制)

一旦任何 PSN 接口返回 `401/403`，系统立即进入 `RISK` 状态并**物理物理熔断**后续所有自动同步。在管理员手动解除风险前，系统拒绝一切登录尝试。

### 7.4 SafePsnClient 策略

- **Token 缓存**: 获取 AccessToken 后缓存至 Redis/内存 1 小时，有效期内严禁重复登录。
- **优雅降级**: 若 PSN 处于熔断状态，系统应保持 Steam 数据正常更新，仅标记 PSN 为“离线隔离”。
