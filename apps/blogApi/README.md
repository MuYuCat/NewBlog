# 🧠 blogApi - 整个博客系统的“智慧大脑” (小白版说明书)

欢迎来到 **NewBlog** 的核心！如果你觉得代码很难懂，没关系，我们把 `blogApi` 想象成一家**高级餐厅**，这样你就全明白了。

---

## 🍽️ 高级餐厅比喻：代码到底在干嘛？

如果把整个博客系统比作一家餐厅：

- **`blogWeb` (前台)**：是餐厅漂亮的**大门和餐桌**，读者在这里看文章。
- **`blogAdmin` (后台)**：是餐厅的**经理办公室**，你在这里改菜单、点货。
- **`blogApi` (本系统)**：就是那间核心的**厨房**。

### 厨房里的核心角色：

1.  **`main.ts` (餐厅开门键)**：
    - **作用**：每天早上第一个按下的开关。它规定了餐厅开在哪个路口（端口 3000），并请好了**拦截器**（负责给外卖打包）和**过滤器**（负责处理客人的投诉）。
2.  **`app.module.ts` (餐厅大管家)**：
    - **作用**：他手里有一张大地图，知道厨房里有哪些部门（比如登录部、文章部、游戏部），并负责把它们协调在一起，不让大家打架。
3.  **`prisma.service.ts` (仓库管理员)**：
    - **作用**：他专门负责跟**仓库 (数据库)** 打交道。你想存菜（存文章）、取菜（读数据）都得找他，他会把你的话翻译成仓库听得懂的语言。
4.  **`auth/` (门卫与认证部)**：
    - **`auth.controller.ts` (接待处)**：负责接收客人的登录请求。他只负责“接活”和“给结果”，如果客人没带证件，他就直接拒之门外。
    - **`auth.service.ts` (保卫科大脑)**：真正干重活的地方。他会去仓库查有没有这个用户，对比密码对不对，并给通过的人发一个“进门证”(JWT Token)。
    - **`auth.module.ts` (保卫科包裹)**：把接待处和大脑打包在一起，方便给大管家调用。

---

## 📂 厨房目录：文件都放在哪？

- **`src/common/` (公共工具箱)**：放着全餐厅共用的工具，比如统一的“打包盒子”。
- **`src/auth/` (登录模块)**：处理所有跟“你是谁”有关的事情。
- **`prisma/` (仓库图纸)**：记录了仓库里每个货架的长宽高（数据表定义）。
- **`node_modules/` (外购食材)**：别人写好的现成工具，我们直接拿来用。

## 💡 核心方法的小白解释

### `onModuleInit()` (开工准备)

- **小白理解**：就像厨师上班第一件事是检查灶台好不好使。在我们的代码里，它会自动检查有没有“老板账号”(MuYuCat)，如果没有，它会自动创建一个，防止你进不去后台。

### `login()` (核对身份)

- **小白理解**：检查用户名和密码。如果对上了，就给你发个证；如果没对上，就告诉你“走错门了”。

### `useGlobalInterceptors` (统一打包)

- **小白理解**：规定所有端出去的菜必须装在统一的盘子里。不管是红烧肉还是蛋炒饭，最后出来的样子都是：`{ "code": 200, "data": ..., "message": "success" }`。

## 🛠️ 如何启动这个“厨房”？

1.  **买菜 (安装依赖)**：在根目录运行 `pnpm install`。
2.  **理货 (同步数据库)**：进入本目录运行 `npx prisma db push`。
3.  **开火 (启动)**：运行 `pnpm run dev:api`。

**记住：厨房稳，餐厅才稳。每一行代码都是为了让数据更安全、更快速地呈献给用户。**
